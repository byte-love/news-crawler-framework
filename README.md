# 新闻抓取框架（引擎部分）

从一套长期无人值守的新闻采集系统里抽出来的公共层。站点脚本只剩十几行配置——搜索接口怎么调、结果怎么解析、翻页怎么翻，其余都在这里。

抽取范围只有三个模块 + 一个日期工具，**不含任何具体站点的配置**：

| 文件 | 职责 |
|---|---|
| `crawler/_cfg.py` | 公共配置与**安全入库层**：时段窗口、字段类型校验、`title != content`、正文长度、断点续跑、库写入前的最后一道闸 |
| `crawler/_generic.py` | **通用抓取器**：给「服务端搜索可用」的站共用。把站点差异参数化成配置，并统一处理详情页正文提取、发布时间解析、栏目筛选与预算控制 |
| `crawler/_ckpt.py` | **跨分片 / 跨机器的关键词断点换算**：历史断点里记录了「哪些关键词跑过了」，按并集还原全量下标，再按目标分片反推每片游标，换机器不用从第 0 个词重跑 |
| `utils/DateChangeUtil.py` | `_cfg` 依赖的日期换算工具 |

## 两条硬底线

框架把「抓回来的内容能不能入库」和「抓取边界怎么判定」收敛到 `_cfg.py` 一处：

1. **入库一律走 `_cfg.SafeStorage`** —— 时间窗、`title != content`、正文长度、字段类型全部检查。
2. **时间窗用 `_cfg.install_window_stop()`** —— 按**真实发布时间**判断边界，不按翻页次数。

## 断点续跑的设计

- 同一个站在不同批次可能用不同分片跑过，`_state_kw/` 里会同时存在 `站名.json`、`站名.s0of3.json`、`站名.s0of4.json`……
- `_ckpt.py` 把这些历史断点还原成「哪些关键词跑过了」的全量下标集合（各来源取**并集**），再按目标分片反推游标。
- 好处：任意分片、任意机器之间都能无缝接力；数据不会重复（入库按 `_id` 去重），但省掉白烧的几小时。
- 安全性：只做并集，不会把没跑过的词标成已跑（除非历史断点本身就错）；关键词表被改过时会整体错位，所以有校验与拒绝。

## 依赖

`requests`、`beautifulsoup4`、`pymongo`、`bson`，Python 3.8+（源码里用了 `from __future__ import annotations`）。

## 说明

- 代码保持原样（只做了脱敏：库地址、库名、产品名换成占位），站点配置与业务消费端不在本仓库内。
- `_cfg.py` 里 `DB_NAME` 与时间窗是示例值，接新批次时改这两处。
